# SelfBlog 全站重设计：清透空间、纵向阅读与导航音乐

- 日期：2026-10-16
- 状态：**视觉方向与书面规格均已获用户确认；按三批计划实施中**
- 适用工程：`frontend/`；本轮不改变后端接口、数据库或发布流程
- 取代范围：2026-10-15 设计中的公开页/后台视觉、圆角和导航表现；保留已实现的品牌资源上传与阅读能力

## 1. 已确认的方向

用户先选择 B「空间手记」，随后明确要求：

1. 整体空间沿用 B，但不要绿色主题。
2. 文章列表使用 A 的纵向排版，不用 B 的双列文章卡片。
3. 圆角明显收小。
4. 导航学习原项目 `https://cam.starsx.top`。
5. 保留最初提出的简约、顺滑动效、液态玻璃装饰与导航音乐控制。

根据这些要求形成的组合预览已获确认：“就这样，太好看了”。实施不得回到大圆角绿色卡片方案，也不再重新选择审美方向。

**一句话设计：B 的空间结构 + A 的文章列表 + 原站紧凑导航；正文安静、控件清透。**

原站实测：桌面导航顶距 16px、高 52px、最大宽 1200px；品牌 → 搜索 → 图标文字导航 → 右侧操作。选中项浅底、强调色、短下划线；滚动主要加深阴影，尺寸稳定。手机为 48px 高，收起桌面搜索与导航入口。

参考 Apple 的 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion) 和 [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)：玻璃主要承载导航与功能控件，不铺满正文；动效短暂、有目的、可减少。

## 3. 范围与拆分

这是一次共享视觉体系下的多批次交付，不是只美化首页。

### 第一批：设计底座、导航与音乐

统一 token、字体、表面、按钮/输入框、焦点、浮层和动效；实现紧凑导航及音乐状态/控制。

### 第二批：公开阅读路径

首页 `/`、文章 `/post/:id`、归档 `/archives`、相册 `/gallery`、搜索 `/search`、标签 `/tag/:id`、关于 `/about`、404；共同页脚、返回顶部、目录与灯箱一并协调。

### 第三批：作者工作台

可配置后台入口、登录、概览、文章管理、写作/编辑器、标签、访客、评论、相册、网站设置。表格、表单、筛选、批量操作、确认框与移动抽屉统一处理。

每一批都有独立计划和验收，不得以只完成 token 或首页替代全站交付。

### 明确不做

- 不迁移 Vue/Pinia/Spring，不引入运行时 UI、图标、动效依赖或远程字体。
- 不重开社区注册、社交入口，不删除仍保留的遗留路由/页面；遗留页面只保证共享样式兼容，不新增社交交互。
- 不修改后端接口、数据表、权限、文章直发和单 JAR 部署流程。
- 不添加歌单、在线音乐平台搜索或跨刷新自动恢复播放。
- 不修改本轮之前已有的根 `CLAUDE.md` 工作区改动。
- 不自动推送、部署、清理数据库或上传目录。

## 4. 视觉系统

### 4.1 配色与字体

默认画布灰白 `#F5F6F8`，内容表面 `#FFFFFF`，主文字 `#262A31`，次文字 `#67707E`，辅助文字使用满足对比度的语义色，分隔线 `#E3E6EC`，强调色为克制蓝。预览蓝 `#3E76CB` 仅作视觉参考；实际作者配置的 `themePrimaryColor` 仍是权威。

深色不是把白色卡片反相：画布约 `#171A20`、表面约 `#20242C`，文字与强调色独立定义。保留语义 `--code-*`、`--contrast-*`；不拿会反转的 `--gray-*` 代替深色代码/高对比表面。

默认不使用绿色。既有五套皮肤与作者显式选择的主色仍可用，不静默覆盖已保存配置。统一推导强调色软底、边框、hover，避免主色变了而残留蓝/绿色组件。

正文与标题使用清晰的系统无衬线中文栈；不再把整站标题/正文交给宋体 display 栈。正文 16–18px、行高约 1.8–1.9；列表摘要 13–14px，辅助信息保持可辨认。代码保留等宽字体。

### 4.2 圆角与表面

| 对象 | 目标 |
| --- | --- |
| 小标签、紧凑元素 | 4–6px |
| 按钮、输入框、工具 hover | 8px |
| 缩略图 | 7–10px |
| 列表分组、后台卡片 | 12–14px |
| 首页介绍区、音乐面板、普通弹窗 | 14–16px |
| 导航外轮廓、头像、播放键 | 按语义保留细长胶囊或圆形 |

通过 `--radius-*` 收敛，不散写数值。导航本身沿用原站细长胶囊，**不能把这一例外扩散成 24–32px 的内容卡片**。

内容表面以实底、细分隔线、轻分组为主，不给每张卡片都堆阴影。玻璃只用于导航、音乐浮层、移动菜单/目录及确有需要的临时控件。通过半透明底、适量背景模糊、细高光和阴影近似质感，不承诺浏览器复刻原生折射。

### 4.3 动效

- 常用 hover/按压约 120–180ms；面板/导航状态约 180–260ms；不把交互锁在动画结束后。
- 以 transform/opacity 为主；不持续动画大面积 blur、阴影、背景或卡片。
- 不让所有文章逐张弹入，不做不断漂浮的背景、不做滚动劫持。
- 深浅切换需同步改变可读的前景/背景，不出现暗底暗字的过渡阶段。
- `prefers-reduced-motion` 下取消位移、缩放、声条循环与平滑滚动；功能与状态文案仍完整。
- 不支持 backdrop-filter、减少透明度或高对比环境使用实底，不能因没有玻璃效果而难以使用。

## 5. 导航与全局布局

- 桌面：顶距 16px、高 **52px**、最大宽 **1200px**，品牌/Logo → 内嵌搜索 → 图标文字导航（首页/归档/相册/关于）→ 音乐/主题工具。
- 浅底选中态与短下划线取代悬浮白色大按钮。搜索聚焦适度扩展，但不得挤到文字换行。
- 中等宽度先将搜索收为图标，音乐去掉文字；约 720px 及以下收起横向导航，改移动菜单。具体断点以 320–1440px 不拥挤为准，不能仅靠文本截断掩盖挤压。
- 手机导航约 **50px** 高、顶距 10px、两侧约 10px。紧凑视觉不等于缩小可点击区域，关键按钮保留约 44px 触达空间，图形可小。
- 360px 及以下优先保留品牌、音乐和菜单，将搜索/主题动作放入移动菜单，避免用 30px 左右的触达宽度硬塞所有按钮。
- 滚动仅轻改透明度、阴影；导航高度恒定。菜单/音乐/搜索打开或内部有焦点时不得自动藏走，本轮也不保留旧的手机下滚隐藏规则。
- 搜索、音乐和菜单互斥；Esc、外部点击与路由切换关闭，并合理恢复焦点。
- 保留 `.app-main` 的 80px 导航占位，公开页自身顶部内距约 24px，手机约 8px；不要把原型里包含导航占位的 main padding 原样再加一次。
- 锚点偏移统一为语义变量，以约 96px 安全区为准；协调 html scroll-padding 与 heading scroll-margin，避免两个大常量叠加。验证原生 hash、目录点击及浏览器返回。

全局弹窗挂载到 `#selfblog` 内、页面 transition 外的稳定 overlay host，避免页面 transform 创建意外层叠上下文，同时保留皮肤/自定义主题变量；不直接传送到会丢失主题继承的裸 body。

层级从低到高：内容 → 固定导航 → 导航非模态浮层 → 模态遮罩/对话框 → 图片灯箱 → 通知。复用/调整统一 z-index token，不在相册里再写孤立的 1000。模态出现时关闭导航浮层。

## 6. 首页与公开页

### 6.1 首页

沿用用户确认的 B 式介绍区和桌面作者侧栏，主体改为 A 式**单列文章列表**。文章所在区域可整体轻分组，不再每篇一张巨大圆角卡。

介绍区使用真实站点配置：siteDescription 作为核心介绍，authorName/authorBio 补充身份，siteTitle 留在品牌位，不重复大字标题。不写死预览的作者姓名或文案。

图片来自已有文章封面：在首批成功加载的数据中选择第一张可用封面作为本次页面停留的介绍区装饰，后续分页不来回换背景；直接打开分页时以该次首批结果为准。没有可用封面或图片失败时使用低对比中性背景，不显示破图、不额外请求相册或新设置接口。展示区尺寸预留，图片到达不造成布局跳动。

原型照片仅用于审美讨论，不提交为产品默认素材。正式文章缩略图尊重原图颜色，不因“不要绿色主题”而强制改色用户照片；介绍区可叠中性渐变保持文字对比。

文章行：日期/分类 → 标题 → 摘要 → 轻量标签/阅读时长；有封面在右侧显示缩略图，无封面不给空槽。默认最新文章可稍加强标题权重，但不强加封面高度。标题是真实链接，标签使用现有标签入口，保留分页、错误重试与空状态；原型的主题切换不代表新建硬编码分类。

桌面侧栏约 224px，主次间距约 24px；960px 及以下提前收起。不得留下 768px 宽度下正文只有约 394px 的旧布局。

### 6.2 文章阅读

正文约 680–760px，按屏幕容纳桌面目录；平板/手机沿用底部目录按钮与抽屉，不挤压正文。标题、摘要、时间、阅读时长形成清楚层级；封面不挡在一切信息之前。

保留 Markdown 净化链路、代码复制/折叠、标题锚点、灯箱、更新日期、相邻文章、匿名点赞与留言。代码横向滚动不带着整页滚动；表格与长链接不撑破页面。阅读进度/标题观察逻辑保持轻量，修改时用相应回归测试保护。

### 6.3 其余公开页

- 归档：清晰的年/月分组与文章行，手机重排日期/标题，保留全部分页归档查询。
- 搜索/标签：复用文章行语言与状态，搜索框清楚聚焦；不展示“点击没反应”的原型筛选。
- 相册：图片主体、适度圆角与清楚锁定提示；保留密码与令牌流程。修复遮罩层级、Esc、焦点回收和背景滚动；统一复用现有灯箱而非两套行为。
- 关于：作者资料主导，移除通用模板说明的大量冗余。
- 页脚、404、返回顶部、目录入口：同一圆角/图标/按钮体系，不与音乐再争右下角位置。

## 7. 导航音乐：单一音频源、多个清楚状态

### 7.1 组件与数据边界

保留 `App.vue` 作为生命周期根。把现有 `MusicPlayer.vue` 改成不带悬浮 UI 的音频宿主，移除右下音乐条；增加 `stores/music.ts` 负责共享状态/动作，以及 `NavbarMusicControl.vue` 负责导航触发器与面板。

音频宿主在 App 内只挂载一次，且不随公开路由、导航折叠或音乐面板开关卸载。store 持有可测试的播放/暂停/进度/音量/循环动作；HTMLAudioElement 由宿主连接，不能让桌面和手机各建一个实例。宿主事件是播放状态权威，不能仅因点击按钮就假定播放成功。

```
siteStore 的 musicEnabled/musicUrl/musicTitle
        ↓
App → MusicPlayer（唯一 audio、事件、设置变化处理）
        ↕
musicStore（状态与控制动作）
        ↕
NavbarMusicControl（导航标记、面板与可访问交互）
```

只复用已有设置，不新建 API、表或“歌曲管理”。后台上传控件继续使用原有 music kind。

### 7.2 交互与生命周期

- 不尝试自动播放；首次用户点播放才调用 play，初始不下载整首音频。
- 导航触发器打开面板；播放/暂停、歌曲名、进度/时长、音量与单曲循环在面板中操作。声条仅播放时运行，减少动效时静止。
- 元数据未加载时显示占位时长，禁用不可用的进度拖动；时长须为有效有限值，不能显示 NaN/Infinity 或伪造原型时长。
- 切换公开页面不中断；进入后台暂停，不在后台自动恢复；返回公开页仍需主动播放。面板销毁不重置歌曲进度。
- 只可记住音量/循环等偏好，localStorage 不可用时降级；刷新页面仍不自动出声。
- 配置禁用或 URL 清空时立即暂停、清理播放/进度并隐藏控件。切换 URL 时暂停旧音源、重置状态，不自动播放新源。
- 防止待决 play Promise、旧音源事件、连续点击与设置变化竞态，不能出现已禁用但晚到的 play 又开始发声。
- 在不支持网页音量调节的平台（例如部分 iOS 媒体实现）明确提示使用设备音量键，不展示伪生效滑块。
- 面板约 300px、圆角 16px，手机不越界，短屏可滚动；不借用另一套巨大的媒体底部抽屉。

### 7.3 状态与错误

| 状态/事件 | 用户可见行为 |
| --- | --- |
| 未配置/禁用 | 无触发器，音频不播放 |
| 就绪但未播放 | 显示音乐入口，点击打开；不偷偷调用 play |
| 正在加载/待决播放 | 清楚等待状态，避免重复操作竞争 |
| playing/pause/ended | 以媒体事件同步图标、文字和进度 |
| play 被浏览器拒绝 | 保持暂停，提示主动播放；不误称文件损坏 |
| 404/网络/格式失败 | 面板内错误与可重试动作，不循环 toast、不影响阅读 |
| 设置被替换/禁用 | 旧源停止，异步回调不得恢复旧播放 |

## 8. 后台工作台

使用相同灰白/深色表面、8px 控件、12–14px 分组。轻透明侧栏/顶栏可以建立层次，但表格和表单必须清晰实底。

- 保留现有后台入口及权限，不增加访客登录入口。
- 侧栏内容仍是现有作者模块；工作区标题、主要动作、筛选/搜索、数据区保持稳定层级。
- 网站设置按身份/外观/音乐/功能等已有字段语义分组，保留上传预览、手填 URL、行内错误、上传后应用与保存持久化约定。
- 文章列表、评论、访客等表格在手机提供合理横向数据区或卡片式行；操作不挤成竖字，不通过隐藏关键操作来“适配”。
- 写作/编辑保留 Markdown、草稿、封面、标签、发布/保存流程；编辑区、工具栏与预览响应式分配空间。
- 登录、确认框、加载/空/失败/保存成功状态同一风格；焦点与键盘行为完整。

## 9. 实施组织与兼容要求

CSS token 仍在 `variables.css`、`dark-mode.css`、`skins.css` 中维护；`main.css` 保持入口职责。只对当前任务涉及的结构做拆分，不用全局选择器覆盖几千行页面样式来伪装重做。

建议的职责边界：

| 单元 | 职责 |
| --- | --- |
| 共享样式/基础组件 | 配色、字体、圆角、触达区域、状态、减少动效与表面降级 |
| Navbar | 响应式导航、搜索、当前路由、浮层互斥，不拥有音频 |
| MusicPlayer / music store / NavbarMusicControl | 唯一音频生命周期 / 状态动作 / 控件呈现 |
| 首页文章行与页面布局 | 内容呈现、无封面退化、现有分页/标签导航 |
| 通用浮层基础设施 | 稳定 portal host、层级、Esc、焦点、滚动锁 |
| 页面与后台模块 | 组合上述组件，保留现有 API 和业务动作 |

不能破坏 Axios 信封契约、动态 adminPath、首次鉴权恢复、site assets 上传、favicon 注入与全站主题配置。任何需要调整这些边界的新发现，应先说明，不暗中扩展范围。

## 10. 验收

### 自动化

- 新增行为先写失败测试，再实现。覆盖导航断点下的交互/路由关闭、音乐成功/失败/竞态/设置变化/偏好/卸载、浮层焦点与滚动恢复、首页无封面及各页面主要行为。
- 媒体以可控制的 HTMLAudioElement 替身测试；rAF 使用可显式刷新的队列；组件测试自动卸载全局监听。
- 必过 `lint:check`、`type-check`、全量 `test:run` 和生产 `build`；既有 17 文件/210 测试不得丢失。纯 CSS 不编造逻辑测试，以浏览器证据验证。
- 只检查改动文件的格式，不运行全仓库自动格式化。若确实需后端改动，另行说明并完整读取相关链路，后端测试须带两个 frontend 插件 skip 参数；当前设计不需要后端修改。

### 浏览器矩阵

320 / 390 / 768 / 820 / 960 / 1024 / 1440px；亮/暗；正常/减少动效；键盘和触摸尺寸。

必须验证：

1. 导航 52px/手机约 50px、滚动不推挤、不竖排；搜索聚焦不挤坏布局。
2. 侧栏在 <=960px 收起，A 式纵向文章列表、无封面无假占位。
3. 正文、长标题、长代码/表格、空/错状态不造成整页横向溢出。
4. 音乐首次不出声、真实播放/暂停/进度/错误、公开换页不断、后台暂停、设置替换停止旧源。
5. 目录/代码复制折叠/锚点/灯箱/留言/匿名点赞保持有效。
6. 相册密码流程不变，遮罩高于导航，关闭恢复焦点/滚动。
7. 后台全部作者入口、上传设置、写作与保存可用，不仅截图好看。
8. 深色文字/按钮/代码块对比清楚；不以切换过程中的截图冒充稳定主题结果。

原型已经通过的检查只证明原型可用，**不等于正式 Vue 实现完成或回归通过**。

## 11. 已作出的取舍

- 取 B 的空间，不取 B 的文章网格：满足个性与扫描效率两种需求。
- 取原站导航的紧凑秩序，不取其社区业务，也不为“动态”强行增加尺寸跳变。
- 默认无绿色，但不删除作者既有主题配置能力。
- 玻璃集中于控件，正文实底；不为装饰牺牲中文可读性和低性能设备。
- 使用已有资料/封面和单曲设置，避免审美重做变成资源后台、歌单和数据库改造。
- 一套视觉分三批验收，不能把前一轮“圆角已替换”当成本轮布局重设计已经完成。
